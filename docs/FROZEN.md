# Python/GiNZA 問題生成バックエンド：凍結

## 決定

サイト運営者の判断により、Python/GiNZA による問題生成バックエンドと、そのサーバー公開に関する作業を一旦凍結する。

削除はしない。後で再開できる状態のまま残す。

## 凍結範囲

- `backend/` 一式（FastAPI、`analyzers/`、`generators/` など）
- `rule_based_qg.py` の移植・統合作業
- `batch_generate.py` の作成
- `render.yaml` と Render へのデプロイ
- Cloud Run、Colab など、サーバー・実行環境の選定

## 凍結理由

1. 自由に使えるPCがなく、GiNZAの検証だけでも環境構築と費用の判断が必要になる。
2. このサイトの中心的な価値は、過去問を集めて見たり解いたりできることにあり、自動生成はその上に乗せる機能である。
3. サイトの利用状況が分からない段階で、サーバー代や運用の手間をかけるのは先走りである。
4. 類題生成や言語解析が必要になった段階でAI等を利用して再開できるため、現時点でここに時間を使う優先度は低い。

## 現在の状態

現時点では、`backend/` にFastAPI・解析器・問題生成器の基盤が存在する。`render.yaml` も存在するが、**未使用・凍結中**であり、Renderへのデプロイは行わない。

既存のフロントエンド `index.html` と `pro_improved.html` は維持する。

## 凍結中の方針

- 既存のファイルを削除しない。
- `backend/` に新しい機能を追加しない。
- `render.yaml` は未使用・凍結中として残す。
- 問題データの共通形式は、後から項目を追加できる拡張可能な形を維持する。
- 凍結作業によって既存HTMLの動作を変更・破壊しない。

## 解凍条件

次のいずれかに該当し、サイト運営者が改めて再開を指示した場合に凍結を解除する。

- サイトを公開し、一定の利用者が付いた。
- 類題生成や言語解析がサイトにとって必要だと判断された。

再開時の実行環境（Colab、借りたPC、有料サーバー等）は、その時点で改めて決定する。

## 次の作業

Python/GiNZA系の作業は凍結し、`backend/` 以外のサイトを完成・公開するための作業を優先する。
